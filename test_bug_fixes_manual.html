Purpose: This page provides manual testing instructions for verifying the fixes for:
  • Bug 1: Game auto-starts after closing Settings modal on intro hub

🎯 Bug 1: Intro Hub Auto-Start Prevention

Test Scenario: Settings Change on Intro Hub

  1. Open the game (intro hub should appear)
  2. Click the Settings button on intro hub
  3. Change the cast members number (e.g., from 12 to 10)
  4. Click Save & Close
✅ Expected Behavior:
  • Settings modal closes
  • User returns to intro hub
  • Game does NOT start automatically
  • Game should ONLY start when user clicks the Play button
🔍 How to Verify:
  • Check that intro hub is still visible after closing settings
  • Verify that window.__bbPlayInitiated is undefined or false
  • Confirm that opening sequence has NOT started

⏸️ Bug 2: Actual Game Pause During Modals

Test Scenario: Settings Modal During Gameplay

  1. Start a game and get to a timed phase (e.g., social phase)
  2. Note the current timer value
  3. Open the Settings modal
  4. Wait for 30+ seconds while modal is open
  5. Close the modal
✅ Expected Behavior:
  • When modal opens, timer freezes (both visually and in game logic)
  • Social AI stops making decisions
  • No phase transitions occur while modal is open
  • When modal closes, timer resumes from where it paused
  • No time is "lost" - the game continues from exact same state
🔍 How to Verify:
  • Check that PauseController.isPaused() returns true when modal is open
  • Verify that game.isGloballyPaused is true during pause
  • Confirm timer value doesn't decrease while modal is open
  • Check that timer resumes from pause point after modal closes

Test Scenario: Other Modals (Rules, DR, Social Summary)

Repeat the same test with:

  • Rules modal
  • Diary Room (DR) button
  • Social summary card ("More" button)

All should pause the game in the same way.
