================================================================================
PLAYER TOTAL UPDATE FIX - IMPLEMENTATION SUMMARY
================================================================================

ISSUE: Users report that changing the Players total from Settings → Cast tab
triggers immediate restart/rebuild or page reload mid-season, interrupting the
current game.

GOAL: Defer player count application until next season or manual refresh, while
preserving lobby behavior (immediate rebuild).

================================================================================
CHANGES IMPLEMENTED
================================================================================

1. DEFERRED MID-SEASON APPLICATION
   - Removed location.reload() calls from mid-season branches
   - Added user-friendly messages: "Players set to X. Will apply next season..."
   - Game continues uninterrupted, roster unchanged
   - Settings persist immediately to config

2. UNIFIED PLAYER RANGE (6-22)
   - Previously inconsistent: 4-16 in some files, 6-22 in others
   - Now unified to 6-22 across all three files
   - Consistent clamping in all UI inputs

3. EVENT HANDLER REFACTORING
   - Removed onChange listeners that called apply functions immediately
   - Added input listeners for UI clamping only (validate 6-22 range)
   - Apply/Save buttons now control when changes are applied

4. PERSISTENCE FLOW UPDATE
   - Added data-key="numPlayers" to injected input
   - applySettingsFromModal() detects numPlayers changes
   - Calls applyPlayersFromSettings() when Apply/Save is clicked
